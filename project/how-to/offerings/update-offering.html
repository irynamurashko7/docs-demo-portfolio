Update an Offering

Add associated categories

You may need to add categories to your Offering to group items associated with it in particular sections on Project pages.

Before you start

Before proceeding with these instructions, make sure to:

  • Find categories where your Offering belongs.

  • Define which of these categories must be the primary one.

An Offering can have only one associated primary category and several secondary ones.

Add a category

This endpoint rewrites the content of the categories array.

Follow these steps only for the first-time adding categories for your Offering.

Activate/deactivate

With this option, you can:

  • Activate your Offering to make it available for purchases after your product integration and development are complete.

  • Deactivate your Offering to make it unavailable for new purchases if you need to sunset it.

Deactivation restricts only new purchases and does not affect existing subscriptions associated with your Offering.

To change your Offering state to/from active, follow these steps:

  1. Authorize in the Backend API Swagger using your Active Directory credentials. Read more here.

  2. Prepare a payload according to one of the following examples in the /offering/update API endpoint and send the request:

    1. Activate example: to activate your Offering.

    2. Deactivate example: to deactivate your Offering.

      To see all available examples in the API specification, click on the Example dropdown.

      Pay attention to the request schema in the API specification since it describes the fields you need to pass and their meaning.

  3. Check the status field in the endpoint response to see the changes.

Allow/restrict multiple quantities for items

You may need this functionality to provide or restrict the possibility for customers to add several equal items associated with your Offering for purchase.

For example, a customer may be able to add several equal phone lines (multiple quantity allowed) but not the same phone number several times for purchase (multiple quantity restricted).

To allow/restrict multiple quantities for items, follow these steps:

  1. Authorize in the Backend API Swagger using your Active Directory credentials. Read more here.

  2. Prepare a payload according to one of the following examples in the /offering/update API endpoint and send the request:

    1. AllowMultipleQuantity example: to allow purchasing several equal items.

    2. RestrictMultipleQuantity example: to restrict purchasing several equal items.

      To see all available examples in the API specification, click on the Example dropdown.

      Pay attention to the request schema in the API specification since it describes the fields you need to pass and their meaning.

  3. Authorize in the Backend API Swagger using your Active Directory credentials. Read more here.

  4. Check the multipleQuantity field in the endpoint response to see the changes.
