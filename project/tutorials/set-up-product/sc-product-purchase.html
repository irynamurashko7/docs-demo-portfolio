Integrate your product purchase into the Shopping Cart

The Shopping Cart allows customers to purchase the products they have added from the partner pages.

You can read more about the Shopping Cart in the Explanations  Shopping Cart section.

After you complete the following steps, customers should be able to add and then purchase your Offering instances via the Shopping Cart.

Before you start

Before proceeding with the integration of product purchases into the Shopping Cart, make sure to:

  • Configure your Pricing Plan.

  • Check that your Pricing Plan price is calculated successfully. You can find the instructions here.

Shopping Cart Integration

Step 1: Set up your Order Processing webhook

Set up an endpoint to process requests from the Core Platform during order processing.

To learn how to create a new service, check out the Create a service document.

Consider the Authorization used for service-to-service communication in the Project when creating your service.

The endpoint must support the following interfaces:

Order Processing webhook request interface. Click to see more details.

Order Processing webhook response interface. Click to see more details. 
// Code block removed due to NDA restrictions.

Your endpoint must respond within the timeout required for this webhook. See the Endpoint Timeouts document for the exact value.

If your endpoint does not respond in time, the Core Platform treats the request as failed and proceeds according to the corresponding failure-handling flow for this webhook.

Partners must support processing of multiple order items per one call.

Checklist

Once completed, you should have an endpoint that can accept requests according to the supported request interface and respond according to the supported response interface.

Step 2: Register your Order Processing webhook

  1. Authorize in the Backend API Swagger using your Active Directory credentials. Read more here.

  2. Prepare a payload for your endpoint according to the CreateOrderProcessingWebhook example in the /webhook/create API endpoint and send the request.

    To see all available examples in the API specification, click on the Example dropdown.

    Pay attention to the request schema in the API specification since it describes the fields you need to pass and their meaning.

  3. Keep the id field value (unique identifier of your webhook) from the endpoint response since you will need it to test your webhook.

Checklist

Once completed, you should have:

  • A created and registered webhook for processing items in the Order Processing phase

  • Your webhook ID

To test your webhook and ensure that it responds as expected, follow these steps:

  1. Prepare the payload you plan to receive at your webhook endpoint. It must correspond to the supported request interface.

  2. Use the prepared payload for the payload field when testing your webhook.

  3. Check the response. It must return the result of order processing on your side and correspond to the supported response interface.

Step 3: Subscribe to events required for product purchase

The Core Platform publishes an Event when something occurs that partners may need to know about, so they can take the necessary actions on their side (for example, subscription renewal).

To subscribe to the events required for product purchase, follow these steps:

  1. Configure your system to process the following events:

    For a subscription Offering. Click to see the list.

    1. backend-api.activated event.

    2. backend-api.deactivated event.

    3. backend-api.subscriptionRenewed event.

    4. backend-api.subscriptionExpirationDatePassed event.

    For a single-purchase Offering. Click to see the list.

    1. backend-api.activated event.

    2. backend-api.deactivated event.

  2. Subscribe to events via the Event Bus to receive notifications about the subscription state.

Step 4: Add a purchase button to your page

  1. Complete the general Core Platform SDK setup according to the instructions here.

  2. Integrate the shared AddItemButton component into your UI to implement a purchase button.

  3. Use the addItem method according to one of the following examples to add an item to the Shopping Cart on the button click:

    1. Add a subscription Offering item example: for an item associated with a subscription Offering.

    2. Add a single-purchase Offering item example: for an item associated with a single-purchase Offering.

Checklist

Once completed, you should have a button on your UI that adds your product to the Shopping Cart for purchase.

Checklist for moving on

After completing this tutorial, you should have a product integrated into the Shopping Cart with the basic settings that you can use as the basis for your integration.

To check that your setup is correct, follow these steps:

  1. Log in to the Project.

  2. Make sure you have enough funds for the test.

  3. Go to your page.

  4. Click the Add to cart button to add the item to the Shopping Cart.

  5. Go to the Shopping Cart.

  6. Proceed with the item purchase.

You can hide the purchase button from customers on your page during the development and while adding more integration settings.

Check the How-to Guides  Customize your Shopping Cart integration  Add an item in development to the Shopping Cart section to learn how to test your product purchases during development.

Troubleshooting

While completing this tutorial, you may face the following issues:

PartnerWebhookRequestTimeoutError. Partner’s webhook request timeout error. Click to see more details.

When occurs:

During order processing, after the Core Platform has sent a request to your webhook

Reason:

Your webhook endpoint did not respond within the expected time window.

How to fix:

To fix this issue, follow these steps:

  1. Check if the product instance is created in your services:

    1. Created: activate the associated Customer Item via the /customerItem/activate API endpoint.

    2. Not created: Refund this order item.

  2. Investigate why your webhook endpoint did not respond within the expected time window. See the Endpoint Timeouts document for the exact value.

InvalidHookResponseError. Order processing failed for order item #43b2c3a1-5c0d-4761-80f7-f8410235f8de. Product purchase requires further actions. error. Click to see more details.

When occurs:

During order processing, after the Core Platform has sent a request to your webhook

Reason:

Your webhook endpoint returned an invalid answer.

How to fix:

To fix this issue, follow these steps:

  1. Check if the product instance is created in your services:

    1. Created: activate the associated Customer Item via the /customerItem/activate API endpoint.

    2. Not created: Refund this order item.

  2. Make sure your webhook response follows the supported response interface.

PricingPlanNotFound. Could not find pricing plans with IDs: 777777 error. Click to see more details.

When occurs:

When adding the item for purchase

Reason:

You passed an invalid Pricing Plan identifier in the item payload.

How to fix:

Pass your Pricing Plan identifier when adding the item for purchase.

Request validation error. Pricing Plan Duration ID must be a `string type, but the final value was: 1234.` error. Click to see more details.

When occurs:

When adding the item for purchase

Reason:

You passed the Pricing Plan Duration identifier in an invalid format.

How to fix:

Pass the Pricing Plan Duration identifier in UUIDv4 format when adding the item for purchase.

PricingPlanDurationNotFound. Could not find pricing plan durations with IDs: #43b2c3a1-5c0d-4761-80f7-f8410235f8de error. Click to see more details.

When occurs:

When adding the item for purchase

Reason:

You passed a non-existent Pricing Plan Duration identifier.

How to fix:

Pass your Pricing Plan Duration identifier when adding the item for purchase.

InvalidPricingPlanParams. Error validating pricing plan params error. Click to see more details.

When occurs:

When adding the item for purchase

Reason:

You tried passing the value for a Parameter of the variable type that is not used in the associated Price Calculation Rule.

How to fix:

Pass values only for Parameters of the variable type used in the associated Price Calculation Rule.

InvalidArguments. Purchase item with a subscription pricing plan #123 with multiple durations cannot be without a period error. Click to see more details.

When occurs:

When adding the item for purchase

Reason:

Your Pricing Plan has several associated Pricing Plan Durations, and you did not pass the identifier of the Pricing Plan Duration to be used for the item.

How to fix:

Pass the identifier of the Pricing Plan Duration to be used when adding the item for purchase.

InvalidArguments. Pricing Plan Duration cannot be applied error. Click to see more details.

When occurs:

When adding the item for purchase

Reason:

You tried passing a Pricing Plan Duration in the item payload for a Pricing Plan associated with a single-purchase Offering.

How to fix:

Skip the Pricing Plan Duration field when adding an item associated with a single-purchase Offering.

Add categories for your Offering. Click to see more details

A Category is an entity the Project pages use to group Offerings and Applications for rendering on the UI. For example, the Shopping Cart pages can group Offerings by categories such as Phone Lines, Voicemail, etc.

First of all, an Offering entity needs a primary category.

A primary category defines the section where the Offering or Application must always belong. All other categories are secondary.

Check the Explanations  Categories document to learn more about categories.

Go to the How-to Guides  Manage Categories section to learn how to work with the categories.

Set up an Application. Click to see more details.

An Application is a UI fragment where users can manage and configure product instances they own or change system and account settings.

The Core Platform uses its discovery system to find such UI fragments.

This discovery system uses associations between various entities (Partners, Offerings, pricing plans, etc.) and Applications to find Applications the customer can use for a particular product instance (for example, Phone Number List, Voicemail Manager, etc.) and render them.

The My Subscriptions Application shows all product instances associated with subscription Offerings except for phone numbers by default. Phone numbers have a dedicated Application - Phone Number List. So, for a subscription Offering, you may delay the Application development.

Product instances associated with single-purchase Offerings require an associated primary Application so users have a place to manage them.

To learn about Applications, check the Explanations  Applications documentation.

To start setting up your first Application, follow the instructions in the Tutorials  Set up an Application.

Set up your product configuration. Click to see more details.

Configuration is a service that teaches users how to use and configure their purchased product instances (Customer Items).

The UI representation of this service is the Configuration Modal, which is used for newly purchased Customer Items and shows the Welcome Screen with first-time user guidance.

Depending on the partner settings, the modal can provide users with options to configure the Customer Item and provide additional instructions to the user.

Read more about it in the Explanations  Configuration documentation.

To start setting up your product configuration, follow the instructions in the Tutorials  Set up your product configuration.
