Configure a Pricing Plan

Each Offering distributed via the Core Platform must have at least one pricing plan.

A Pricing Plan is an entity that contains information about the billing cycle period (for a subscription Offering) and a price calculation rule.

Each price calculation rule must have a formula expression and default values for all used parameters.

The formula expression can use the `name`s of one or several parameters combined in arithmetic, comparison, and ternary operations to describe the price calculation rules.

A Parameter is a placeholder used in a price calculation rule to represent a value that may change.

Since each parameter is global, several price calculation rules associated with your Partner entity can use it. Therefore, it must have a unique name.

The default parameter values serve as a fallback for all pricing plans using this price calculation rule.

Before you start

Before proceeding with configuring your Pricing Plan, make sure to configure your Offering entity.

Pricing Plan Configuration

You must complete the Pricing Plan Configuration manually via Swagger since this API is intended for manual actions only.

In this tutorial, the product price is fixed and consists of the following parts:

  • A part that may change from time to time (but not at runtime during purchase) and is equal to 1 cent

  • A part that never changes and is equal to 1 cent

So, we need the following price calculation rule:

basePrice + 1

Where:

  • basePrice is a constant Parameter with the value equal to 1

  • 1 is the price part that should never change

To configure a Pricing Plan, follow these steps:

Step 1: Authorize in Swagger

If you are still authorized in Swagger after configuring your Offering entity, you can skip this step and proceed with creating a Parameter.

To proceed, you need to authorize in the Backend API Swagger using your Active Directory credentials. Read more here.

Step 2: Create a Parameter

  1. Prepare a payload according to the CreateConstant example in the /parameter/create API endpoint and send the request.

    To see all available examples in the API specification, click on the Example dropdown.

    Pay attention to the request schema in the API specification since it describes the fields you need to pass and their meaning.

  2. Keep the following data from the endpoint response since you will need it in the next steps:

    1. id field value - a unique identifier of your Parameter

    2. name field value - the name of the Parameter you will use in the formula expression in the next step.

Checklist

Once completed, you should have:

  • A created Parameter

  • Your Parameter ID

  • Your Parameter name

To double-check, pass your Parameter identifier as the parameterId in your request to the /parameter/read API endpoint and check the response.

Step 3: Create a Price Calculation Rule

  1. Convert your basePrice + 1 formula expression to a serialized JSON object. You can use an online JSON formatter tool.

  2. Prepare a payload according to the CreatePriceCalculationRule example in the /price-calculation-rule/create API endpoint, using the converted formula expression for the formula field, and then send the request.

    To see all available examples in the API specification, click on the Example dropdown.

    Pay attention to the request schema in the API specification since it describes the fields you need to pass and their meaning.

  3. Keep the id field value (unique identifier of your Price Calculation Rule) from the endpoint response since you will need it in the next step when creating a Pricing Plan entity.

If you get an error in the response, check the most common error troubleshooting instructions.

Checklist

Once completed, you should have:

  • A created Price Calculation Rule

  • Your Price Calculation Rule ID

To double-check, pass your Price Calculation Rule identifier as the priceCalculationRuleId in your request to the /price-calculation-rule/read API endpoint and check the response.

Step 4: Create a Pricing Plan

  1. Prepare a payload according to one of the following examples in the /pricingPlan/create API endpoint and send the request:

    1. CreatePaidSubscriptionOfferingPlan: for a plan associated with a subscription Offering

    2. CreatePaidSinglePurchaseOfferingPlan: for a plan associated with a single-purchase Offering.

      The period field is mandatory for Pricing Plans associated with subscription Offerings and not allowed for those associated with single-purchase Offerings.

      Core Platform uses this field value to automatically create a default Pricing Plan Duration for the Pricing Plan.

      To see all available examples in the API specification, click on the Example dropdown.

      Pay attention to the request schema in the API specification since it describes the fields you need to pass and their meaning.

  2. Keep the following data from the endpoint response since you will need it in the next steps:

    1. id field value - a unique identifier of your Pricing Plan

    2. slug field value - a unique human-readable identifier of your Pricing Plan

    3. durationId field value (for a plan associated with a subscription Offering) - a unique identifier of your Pricing Plan Duration.

If you get an error in the response, check the most common error troubleshooting instructions.

Checklist

Once completed, you should have:

  • A created Pricing Plan

  • Your Pricing Plan ID

  • Your Pricing Plan slug

  • An automatically created Pricing Plan Duration (for a plan associated with a subscription Offering)

  • Your Pricing Plan Duration ID (for a plan associated with a subscription Offering)

To double-check, follow these steps:

  1. Authorize with your Active Directory credentials in the Backend API Swagger.

  2. Pass the slugs of your Pricing Plan and the associated Offering and Partner entities from the previous tutorial steps in your request to the /pricingPlan/readBySlug API endpoint.

  3. Check the endpoint response.

Checklist for moving on

On completing this tutorial, you should have:

  • The simplest representation of your service in the Core Platform that you can use as a basis and add other product-specific functionality

  • The identifiers of the following entities that represent your service in the Core Platform:

    • Partner

    • Offering

    • Pricing Plan

    • Pricing Plan Duration (for a plan associated with a subscription Offering only)

    • Price Calculation Rule

    • Parameters

To check that your configuration is correct, follow these steps:

  1. Authorize with your Active Directory credentials in the Backend API Swagger.

  2. Pass the slugs of your Pricing Plan and the associated Offering and Partner entities in your request to the /price/calculate API endpoint.

  3. Check the endpoint response to make sure the price is calculated as expected.

If you get an error in the response, check the most common error troubleshooting instructions.

Troubleshooting

While completing this tutorial, you may face the following issues:

Parameter(s) do not exist error. Click to see more details.

When occurs:

In the /price-calculation-rule/create API endpoint response

Reason:

You try using a Parameter that was not created before.

How to fix:

Create this Parameter before using it in the Price Calculation Rule.

child \"period_iso_8601\" fails because [\"period_iso_8601\" is required] error. Click to see more details.

When occurs:

In the /pricingPlan/create API endpoint response

Reason:

The associated Offering entity type is a subscription one, and you did not pass the period field in your request payload.

How to fix:

Pass the period field equal to the default billing cycle you need for the Pricing Plan in your request payload when creating the Pricing Plan.

child \"period_iso_8601\" fails because [\"period_iso_8601\" is not allowed] error. Click to see more details.

When occurs:

In the /pricingPlan/create API endpoint response

Reason:

The associated Offering entity is a single-purchase one, and you passed the period field in your request payload.

How to fix:

Pass the request payload without the period field to create your Pricing Plan associated with a single-purchase Offering.

Undefined symbol <parameter_name> error. Click to see more details.

When occurs:

When you try calculating the Pricing Plan prices

Reason:

Mismatch of the Parameters used in the formula expression and the Parameters you have set default values for in your Price Calculation Rule.

How to fix:

Retrieve your Price Calculation Rule via the /price-calculation-rule/read API endpoint and check if its parameterValues field contains the default values for all Parameters used in the formula expression.
