Glossary

This section provides definitions of the key terms used in the Core Platform.

A

Add-on Pricing Plan

An Add-on Pricing Plan is a specific pricing plan that customers can purchase only with particular pricing plans or for an existing Customer Item associated with one of these pricing plans. Such pricing plans are called Parent Pricing Plans, and such a Customer Item is called a Parent Customer Item.

Read more here.

Application

An Application is a UI fragment where users can manage and configure product instances they own or change system and account settings.

The Core Platform uses its discovery system to find such UI fragments.

This discovery system uses associations between various entities (Partners, Offerings, pricing plans, etc.) and Applications to find Applications the customer can use for a particular product instance (for example, Phone Number List, Voicemail Manager, etc.) and render them.

Asset

An Asset is a color, an icon, or an image set for an entity (category, Offering, Application, etc.) that is always accessible on Project.

B

Billing Cycle

A Billing Cycle is the time between two consecutive billing invoices for subscription Offerings.

Read more here.

Billing Strategy

A Billing Strategy represents a set of days before or after the subscription expiration date when a payment event should be triggered.

It includes configurations for renewal notifications for regular subscriptions and charge attempts for regular and trial subscriptions.

C

Category

A Category is an entity the Project pages use to group Offerings and Applications for rendering on the UI. For example, the Shopping Cart pages can group Offerings by categories such as Phone Lines, Voicemail, etc.

When assigning a category to an Offering or Application, you must indicate if this category will be the primary one.

A primary category defines the section where the Offering or Application must always belong. All other categories are secondary.

Configuration

Configuration is a service that teaches users how to use and configure their purchased product instances (Customer Items).

Customer Item

A Customer Item is an entity that can represent both subscription and single-purchase Offerings purchased within the Core Platform and owned by the customer. This entity also stores Offering-related information and data about the associated subscriptions (for subscription Offerings).

E

Event

The Core Platform publishes an Event when something occurs that partners may need to know about, so they can take the necessary actions on their side (for example, subscription renewal).

F

Free Product

A Free Product is an item that customers automatically receive free of charge under certain conditions.

The purchase price of such products is always zero.

For example, after purchasing a phone line, the customer must receive the default voicemail service unless they connect it to another product, such as a call routing service, from the start.

Such product instances are created via API and skip the payment process.

G

Grace Period

A Grace Period represents the days after the expiration date when a subscription remains active on the Core Platform side. Partners can use this period, for example, to allow customers to renew their subscriptions even if all scheduled charge attempts failed for some reason.

L

Landing Page

A Landing Page is a UI fragment devoted to a particular Offering.

Such a page provides users with detailed information about the Offering, a comparison of the associated pricing plans (if there are several), and an option to purchase them.

Launchpad

The Launchpad is a system where users start their Project journey, see new notifications, add more products and tools, and launch any Applications installed in their account.

Localization Resource

A Localization Resource allows localizing and customizing parts of the website related to an entity (Application, Offering, pricing plan, category, etc.). For example, you can use it for titles, descriptions, or features that must be shown for a particular pricing plan.

M

MiniCart

The MiniCart a panel that provides quick access to items added to the Shopping Cart, allowing users to proceed with their purchase immediately or go to the Shopping Cart to customize them before purchase.

N

Notification Center

The Notification Center is a centralized system designed to streamline and standardize the delivery of UI notifications from all products within the Project ecosystem to users.

Users can find notifications about all events in their account (for example, completed orders, items requiring attention, delayed operations, etc.) in the Notification Center.

O

Offering

Offering entities represent different variations of the service offered within the Partner. For example, if you want to target your services to individual and business customers, your Phone Service Partner can have two Offerings: Residential Phone Line and Business Phone Line.

Each Offering distributed via the Core Platform must have at least one pricing plan.

Read more here.

Order

An Order is an entity that stores information about order status, payment terms, invoice details, the customer, and the items the customer is trying to get in a single batch. These items can include purchases of subscription or single-purchase Offerings, Offerings provided free of charge, subscription renewals, or subscription plan updates.

P

Parameter

A Parameter is a placeholder used in a price calculation rule to represent a value that may change.

Since each parameter is global, several price calculation rules associated with your Partner entity can use it. Therefore, it must have a unique name.

Each parameter requires a value that the Core Platform will use during price calculation.

Partner

The term partner with a lowercase p refers to a consumer of the Core Platform functionality. On the other hand, the Partner with a capital P refers to a backend entity in the Core Platform.

The Partner entity represents the service you intend to offer your customers in the Project ecosystem (for example, a Phone Service Partner allowing customers to get phone lines for voice communication).

Pre-authorization

Pre-authorization is a process of verifying the customer by charging and immediately refunding a small nominal amount (e.g., $0.05 or its equivalent in the customer’s currency) to their selected payment method.

Pre-authorization occurs if the Partner enables this option and the final total of the order is $0.00 (for example, for trial or usage-based subscriptions). This process helps to prevent fraudulent purchases by validating the customer’s payment method.

Prepaid Product

A Prepaid Product is an item the customers can purchase via the Shopping Cart. During the purchase, they must pay for the item for one or several billing periods.

The price of such a product may be equal to or higher than zero.

Partners can also switch the payment for the product on and off at any point if necessary.

For example, the partner can sell a phone line service to customers via the Shopping Cart and have a giveaway free of charge at some point.

Price Calculation Rule

A Price Calculation Rule is an entity that describes the product price.

Each price calculation rule must have a formula expression and default values for all used parameters.

The formula expression can use the `name`s of one or several parameters combined in arithmetic, comparison, and ternary operations to describe the price calculation rules.

The default parameter values serve as a fallback for all pricing plans using this price calculation rule.

Pricing Plan

A Pricing Plan is an entity that contains information about the billing cycle period (for a subscription Offering) and a price calculation rule.

The pricing plan assigned to an Offering defines its price based on the configured billing cycle, price calculation rule, and designated values.

Read more here.

Pricing Plan Duration

A Pricing Plan Duration describes an interval between the start of a billing cycle and its end and the settings that depend on it.

A pricing plan can have several durations.

Pricing Plan Feature

A Pricing Plan Feature is a text description of a pricing plan characteristic. It may or may not relate to the price calculation. For example, the Business Phone Line Offering has the call recording storage feature that is provided in various amounts for various pricing plans by default and does not affect the price.

Promotion

A Promotion is an entity that defines the time frames, scope, parameters, and priority of a particular discount.

Core Platform can find promotions in the following ways:

  • Automatically (auto promo)

  • Upon user action (when they enter a valid promotion code)

Each promotion has a set of parameters that define the circumstances under which it should be applied. Partners can flexibly configure the scope of the promotion application using the promotion parameters, Promotion Codes, and Promotion Limits.

Promotion Code

A Promotion Code activates the promotion. So, to take advantage of the promotion, the user must enter the associated code.

Promotion Limit

A Promotion Limit sets the maximum number of times (threshold) for promotion usage.

S

Shopping Cart

The Shopping Cart allows customers to purchase the products they have added from the partner pages. Its primary purpose is to provide a convenient, user-friendly way for customers to manage their selected items before proceeding to checkout.

Read more here.

Slug

A Slug is a unique identifier of an entity (Partner, Offering, pricing plan, etc.) in an easy-to-read form.

For example, a phone services provider can have a residential-phone-line slug for their Residential Phone Line Offering entity and use it as an identifier for this Offering entity.

Subscription

A Subscription represents a billing model where the customer pays a fixed price at regular intervals (for example, monthly or yearly) to use a product or service.

The subscription model helps partners in the following areas:

  • Automate the regular billing for customers.

  • Perform actions in the Customer Items based on subscription lifecycle events. For example, terminate access to resources on subscription expiration.

Subscription entities are created for subscription Offerings only.

Subscription Notification Settings

Subscription Notification Settings allow partners to set notifications to a particular time during the subscription lifecycle.

Subscription Pause

A Pause is a period of temporary interruption of service without permanent subscription termination.

Suggestion

A Suggestion is a recommendation of product customers usually purchase together with the item the customer views or purchases. When used together, such products supplement each other’s functionality (for example, a phone line and voicemail).

T

Trial Period

A Trial period lets customers try a subscription for free before buying it. During this time, they can test its features and see if it fits their needs.

The trial period doesn’t count as a billing cycle. If the customer decides to continue after the trial, the first billing cycle starts after the trial subscription renewal or when they purchase the regular subscription.

U

Usage-based Product

A Usage-based Product is an item that customers pay for based on their actual usage of allocated resources.

The purchase price of such products is zero.

After one billing period, the customer must pay for the amount of resources they actually consumed during that period (for example, the number of minutes used on a phone line).

V

Value

A Value is a specific numerical or symbolic representation assigned to a parameter.

Numeric values are configured in cents and can have decimal values. For example, the value specified as 20.25 means $0.2025. During price calculation, the resulting price in dollars is rounded to 2 digits after the decimal point for regular pricing plans and 8 digits after the decimal point for usage-based pricing plans.

There are the following types of values:

Default value

For parameters, a default value is a mandatory value that is set during price calculation rule creation or update. When the Core Platform cannot find a custom value for a parameter, it uses the specified default value as a fallback.

Custom value

This value is assigned to a parameter for a particular entity (Partner, Offering, pricing plan, pricing plan duration) and overrides the default value for that entity. You can use it to set various values to the same parameter. For example, you can set the basePrice parameter to $5 for pricing plan 1 and $10 for pricing plan 2.

W

Webhook

A Webhook is an endpoint the Core Platform uses to send real-time data to notify the Partner when a specific event occurs and exchange data required to proceed with a particular flow (item purchase, subscription renewal, etc.).

Widget

A widget is an independent UI (user interface) element that displays information about a product and allows users to interact with it.
