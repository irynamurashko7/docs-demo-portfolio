Shopping Cart

Overview

The Shopping Cart allows customers to purchase the products they have added from the partner pages. Its primary purpose is to provide a convenient, user-friendly way for customers to manage their selected items before proceeding to checkout.

For a product purchase, both logged-in and guest users (persons who are not logged in) can add items to the Shopping Cart.

If the customer added some products as a guest user and then decided to log in, the Shopping Cart will be overwritten with the products they added as a guest user.

If a user added items to the Shopping Cart but didn’t proceed with a checkout, the items will be stored in the cart as follows:

  • For a logged-in user: indefinitely until the user decides to check out or delete them from the cart

  • For a guest user: for 7 days until the session expires.

The Shopping Cart allows adding the following purchase types:

  • Product Purchase

  • Subscription Renewal

  • Subscription Plan Update

Cart Item

The Partner creates their page with an option for customers to add their products to the Shopping Cart right from the page. Once an item is added to the Shopping Cart, it is treated as a cart item.

Order Item

During the Shopping Cart flow, the Core Platform creates an order for the purchase. Once the order is created, the cart item becomes an order item.

For a cart item with a quantity of more than 1 (for example, 2 or more of the same phone line package), a single order item is created. Each of these items in the order item will get its Customer Item ID and, for a subscription Offering, a subscription ID.

Customer Item

A Customer Item is an entity that can represent both subscription and single-purchase Offerings purchased within the Core Platform and owned by the customer. This entity also stores Offering-related information and data about the associated subscriptions (for subscription Offerings).

Please check the Customer Items document for more information about the Customer Item entity.

Subscription

Subscription Offering instances also get a Subscription entity.

A Subscription represents a billing model where the customer pays a fixed price at regular intervals (for example, monthly or yearly) to use a product or service.

The subscription model helps partners in the following areas:

  • Automate the regular billing for customers.

  • Perform actions in the Customer Items based on subscription lifecycle events. For example, terminate access to resources on subscription expiration.

Please check the Subscriptions document for more information about the subscription lifecycle.

Webhooks

In the Core Platform, the purchase flow has several places where the next step may vary. These places are called execution phases.

The partner can set up a webhook and register it for a particular execution phase. A webhook is a mechanism that allows one service to send real-time data to another service when a specific event occurs. This webhook will help the Core Platform to define (based on the response it returns) the next step when the purchase flow reaches the execution phase.

Check this document for payload and response references for each webhook.

Shopping Cart UI

On the UI, the Shopping Cart is represented with the following pages and screens:

  • Shopping Cart page

  • Order Processing page

  • Purchase Summary page

Shopping Cart and Purchase Summary pages use widgets to display items.

To show customers that widgets are still loading, the Shopping Cart system uses the Skeleton Loader component from the Shared Components Library for all widgets (default and custom) by default.

Shopping Cart page

This page renders Shopping Cart widgets (default or custom) to display cart items. As a result, the customer can check information about the added items, select available configuration options, add a promo code (if they have any) and then proceed with the purchase.

Recommended Items section displays suggestions of products that can be used together with the item added to the Shopping Cart, enabling the customer to purchase them simultaneously right away.

Order Processing page

This page shows the current state of the order processing to the customer if it takes more than 5 seconds.

Purchase Summary page

On this page, the customer can see the order summary with details of the purchased items displayed via Purchase Summary widgets (default or custom). Depending on the processing status, the items are divided into 2 sections: successfully purchased and failed. The failed items are refunded automatically.

Check the Widgets document to learn more.

This page also provides the customer with an option to download the order receipt in PDF format.

UI customization options

Core Platform provides options to customize the look of the products in the Shopping Cart. These include widgets.

Widgets

A widget is an independent UI (user interface) element that displays information about a product and allows users to interact with it. Check the Widgets document to learn more.
